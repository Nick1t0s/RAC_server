# ТЗ для Claude Code: Сервер удалённого управления ПК

## 0. Контекст

Нужно реализовать **серверную часть** системы удалённого управления ПК. Клиент-агент, который ставится на удалённые машины, **вне рамок задачи** — но сервер должен корректно с ним общаться по описанному ниже HTTP-протоколу.

Сервер совмещает в одном FastAPI-приложении:
- API для агентов (опрос очереди команд, отчёты о выполнении, обмен файлами);
- веб-админку с консолью, проводником и загрузкой файлов.

Хранилище — общая SQLite-база + файловая система (`cmds/` и `uploads/`).

## 1. Стек

- Python 3.11+
- FastAPI, Uvicorn
- Jinja2 (шаблоны), python-multipart, aiofiles
- sqlite3 (стандартная библиотека, **без ORM**)
- PyYAML, passlib[bcrypt], itsdangerous
- Фронтенд: Jinja2 + ванильный JS, без сборщиков и SPA-фреймворков
- CSS: можно использовать Tailwind через CDN (`https://cdn.tailwindcss.com`) — это упростит адаптивную вёрстку. Допустимо и обычный CSS, на твоё усмотрение.

Запуск: `python main.py` (внутри сам поднимает uvicorn с параметрами из config.yaml).

Зависимости — `requirements.txt`.

## 3. Конфигурация (config.yaml)

```yaml
server:
  host: "0.0.0.0"
  port: 8000

auth:
  username: "admin"
  password_hash: "REPLACE_ME_RUN_generate_password.py"
  session_secret: "REPLACE_ME_LONG_RANDOM_STRING"
  session_lifetime_hours: 24

storage:
  cmds_dir: "./cmds"
  uploads_dir: "./uploads"
  db_path: "./data.db"
  max_upload_size_mb: 100

polling:
  agent_poll_interval_sec: 2   # информативно, для документации агента
  online_threshold_sec: 30     # если last_seen свежее — устройство считается online
```

При старте сервер валидирует конфиг и **отказывается запускаться**, если:
- `password_hash` начинается с `REPLACE_ME` или пустой;
- `session_secret` начинается с `REPLACE_ME` или короче 32 символов.

В этом случае пишет понятное сообщение, что нужно запустить `python generate_password.py` и заменить плейсхолдеры.

## 4. Утилита `generate_password.py`

CLI-скрипт. При запуске:
1. Запрашивает пароль через `getpass` (без эха), потом подтверждение.
2. Генерирует bcrypt-хэш.
3. Генерирует случайный `session_secret` через `secrets.token_urlsafe(48)`.
4. Печатает оба значения с инструкцией вставить в `config.yaml`.

Не редактирует `config.yaml` сам — только печатает.

## 5. Схема БД (SQLite)

Создаётся автоматически при старте, если файла нет. Используются `PRAGMA foreign_keys = ON` и `PRAGMA journal_mode = WAL`.

### `devices`
```sql
CREATE TABLE devices (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  mac         TEXT NOT NULL,
  hostname    TEXT NOT NULL,
  last_ip     TEXT,
  token       TEXT NOT NULL UNIQUE,
  first_seen  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_seen   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(mac, hostname)
);
CREATE INDEX idx_devices_token ON devices(token);
```

### `commands`
```sql
CREATE TABLE commands (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id         INTEGER NOT NULL REFERENCES devices(id),
  name              TEXT NOT NULL,
  payload           TEXT NOT NULL DEFAULT '',
  status            TEXT NOT NULL DEFAULT 'pending',  -- pending | in_progress | done | error
  output            TEXT NOT NULL DEFAULT '',
  input_file_path   TEXT,    -- файл, прикреплённый АДМИНОМ к команде (относительно uploads_dir)
  output_file_path  TEXT,    -- файл, ВЕРНУВШИЙСЯ от агента (относительно cmds_dir)
  created_at        TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  taken_at          TIMESTAMP,
  completed_at      TIMESTAMP
);
CREATE INDEX idx_commands_device_status ON commands(device_id, status);
CREATE INDEX idx_commands_device_created ON commands(device_id, created_at DESC);
```

### `uploads`
```sql
CREATE TABLE uploads (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  filename        TEXT NOT NULL,         -- оригинальное имя
  stored_path     TEXT NOT NULL UNIQUE,  -- относительно uploads_dir, формат {timestamp}_{filename}
  size_bytes      INTEGER NOT NULL,
  uploaded_at     TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

База **не чистится автоматически** — вся история сохраняется навсегда.

## 6. API для агентов

Базовый префикс: `/api/agent/`. Все эндпоинты, кроме `/register`, требуют заголовок `Authorization: Bearer <token>`. Без токена или с невалидным — `401 Unauthorized`.

Dependency `get_current_device(authorization)` извлекает токен, ищет устройство, обновляет `last_seen` и `last_ip` (IP берётся из `request.client.host`, с учётом возможного `X-Forwarded-For`).

### 6.1 `POST /api/agent/register`
Регистрация устройства при первом запуске агента. Без авторизации.

**Request (JSON):**
```json
{ "mac": "AA:BB:CC:DD:EE:FF", "hostname": "USER-PC", "ip": "192.168.1.10" }
```

Все три поля обязательны. Валидация: MAC по regex `^([0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}$` (нормализуется в верхний регистр с `:`). `hostname` — непустая строка до 255 символов.

**Логика:**
- Если в `devices` уже есть запись с такой парой `(mac, hostname)` — обновляется `last_ip`, `last_seen`, **возвращается существующий токен** (агент мог потерять локально — это позволит ему восстановиться).
- Если нет — создаётся новая запись, генерируется токен `secrets.token_urlsafe(32)`.

**Response (200):**
```json
{ "device_id": 5, "token": "abc...xyz" }
```

### 6.2 `GET /api/agent/command`
Получить следующую команду (FIFO) для устройства.

**Логика (в одной транзакции):**
1. Найти команду с минимальным `id` для `device_id == current.id` и `status == 'pending'`.
2. Если есть — обновить `status = 'in_progress'`, `taken_at = NOW`.
3. Вернуть JSON.

**Response (200), если команда есть:**
```json
{
  "command_id": 42,
  "name": "screenshot",
  "payload": "fullscreen --quality=80",
  "has_file": false,
  "file_url": null
}
```

Если у команды есть `input_file_path` — `has_file = true` и `file_url = "/api/agent/command/42/file"`.

**Response 204 No Content** — если команд нет.

### 6.3 `GET /api/agent/command/{command_id}/file`
Скачать файл, прикреплённый админом к команде.

**Проверки:**
- Команда существует и принадлежит устройству агента.
- У команды есть `input_file_path`.
- Файл реально существует на диске.

**Response:** `FileResponse` с оригинальным именем файла (берётся из `uploads.filename`), Content-Type `application/octet-stream`.

Ошибки: 404 если команды нет / файла нет / команда не принадлежит устройству.

### 6.4 `POST /api/agent/result`
Отчёт о выполнении команды. Принимает **multipart/form-data**.

**Form fields:**
| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| command_id | int | да | ID команды |
| status | str | да | `done` или `error` |
| output | str | да | Текстовый вывод (может быть пустой строкой) |
| file | file | нет | Опциональный файл-результат |

**Логика:**
1. Проверить, что команда существует, принадлежит устройству агента и в статусе `in_progress` (если уже `done`/`error` — вернуть 409 Conflict).
2. Если есть файл:
   - `sanitized_cmd_name = re.sub(r'[^A-Za-z0-9_-]', '_', name)` (имя из таблицы commands).
   - `sanitized_filename = sanitize_filename(original_filename)` — убрать `..`, разделители путей, нулевые байты, control characters; если после санитизации пусто — использовать `file`.
   - `timestamp = strftime('%Y%m%d_%H%M%S')`.
   - Целевой путь: `{cmds_dir}/{sanitized_cmd_name}/{timestamp}_{sanitized_filename}`.
   - Создать директорию.
   - Записать файл стримом, отслеживая размер. Если превышен `max_upload_size_mb` — оборвать, удалить недописанный файл, вернуть 413.
   - В БД сохранить относительный путь (от `cmds_dir`).
3. Обновить команду: `status`, `output`, `output_file_path` (если был файл), `completed_at = NOW`.

**Response (200):** `{"ok": true}`

Ошибки: 400 (невалидный status), 404 (нет команды), 409 (уже завершена), 413 (файл слишком большой).

## 7. Веб-API (для админки)

Базовый префикс: `/api/web/`. Все эндпоинты требуют валидной сессии (cookie). Без неё — 401 для API, редирект на `/login` для страниц.

### 7.1 Устройства
- `GET /api/web/devices` → массив `{id, mac, hostname, last_ip, last_seen, online}`. `online = (now - last_seen) < online_threshold_sec`.

### 7.2 Команды
- `GET /api/web/commands?device_id=X&limit=100&before_id=Y` → массив команд устройства, отсортирован по `id DESC`. `before_id` для пагинации (загрузить старее). Каждая команда содержит:
  ```json
  {
    "id": 42, "name": "...", "payload": "...", "status": "done",
    "output": "...", "created_at": "...", "completed_at": "...",
    "input_file": { "filename": "report.pdf", "url": "/api/web/uploads/3/download" } | null,
    "output_file": { "filename": "20260427_120000_screen.png",
                     "url": "/api/web/files/download?path=screenshot/20260427_120000_screen.png" } | null
  }
  ```
- `POST /api/web/commands` (JSON) → создать команду:
  ```json
  { "device_id": 5, "name": "screenshot", "payload": "...", "upload_id": 3 }
  ```
  `upload_id` — опциональный, ссылка на запись в `uploads`. Если указан — в команду пишется `input_file_path` из этой записи. Имя `name` обязательно, не пустое, до 64 символов.

### 7.3 Загрузки админа (uploads)
- `GET /api/web/uploads` → список всех загрузок (id, filename, size, uploaded_at).
- `POST /api/web/uploads` (multipart, поле `file`) → принять файл, сохранить в `{uploads_dir}/{timestamp}_{sanitized_filename}`, создать запись в `uploads`. Лимит размера — тот же `max_upload_size_mb`. Возвращает `{id, filename, stored_path, size_bytes}`.
- `GET /api/web/uploads/{id}/download` → скачать файл (для предпросмотра в UI).
- `DELETE /api/web/uploads/{id}` → удалить файл и запись. **Не разрешать удаление**, если на этот upload ссылается хоть одна команда (вернуть 409 со списком id команд).

### 7.4 Проводник `cmds/`
- `GET /api/web/files?path=screenshot` → содержимое директории. Возвращает:
  ```json
  {
    "path": "screenshot",
    "parent": "",
    "items": [
      {"name": "subfolder", "type": "dir"},
      {"name": "20260427_120000_screen.png", "type": "file", "size": 12345, "mtime": "..."}
    ]
  }
  ```
  При `path=""` — корень `cmds/`.
- `GET /api/web/files/download?path=screenshot/20260427_120000_screen.png` → отдать файл.
- `DELETE /api/web/files?path=...` → удалить файл (только файлы, не директории).

**Все пути проходят через `safe_path(base, user_path)`** — нормализация через `os.path.realpath`, проверка `commonpath == realpath(base)`. Любая попытка выйти за пределы → 400.

## 8. Веб-страницы (Jinja)

### 8.1 `GET /login`, `POST /login`, `POST /logout`
- `login.html` — простая форма (username, password).
- POST: проверка пароля через `bcrypt.verify`, при успехе — установка сессионной cookie (`SessionMiddleware` от starlette с `session_secret` из конфига, `max_age = session_lifetime_hours * 3600`, `httponly=True`, `samesite=lax`).
- Logout: очистка сессии, редирект на `/login`.

### 8.2 `GET /` — главная страница
Серверный рендер только каркаса. Все данные грузятся через JS из `/api/web/*`.

#### Десктоп-вёрстка (≥ 768px)
```
┌──────────────────────────────────────────────────────────────┐
│  Header: [Устройство ▾]   [● online]      admin · [Logout]   │
├──────────────────────────────────────────┬───────────────────┤
│                                          │                   │
│   КОНСОЛЬ                                │  ПРОВОДНИК /cmds  │
│  ┌───────────────────────────────────┐   │  📁 screenshot    │
│  │ #15 [done] ls -la                 │   │  📁 sysinfo       │
│  │     output: ...                   │   │                   │
│  │     [⬇ output.txt]                │   │  > screenshot/    │
│  │ #16 [pending] reboot              │   │  📄 ..._a.png     │
│  │     ↑ input file: report.pdf      │   │     [⬇] [🗑]      │
│  │ ...                               │   │                   │
│  └───────────────────────────────────┘   │  ─────────────    │
│                                          │  UPLOADS          │
│  Имя команды: [_________]                │  📄 report.pdf    │
│  Payload:     [_________]                │     [⬇] [🗑]      │
│  Файл:        [▾ Без файла]              │  [+ Загрузить]    │
│  [Отправить]                             │                   │
└──────────────────────────────────────────┴───────────────────┘
```

#### Мобильная вёрстка (< 768px)
- Header сжимается (только селектор устройства + меню-гамбургер с logout).
- Под header — табы: **[ Консоль ] [ Файлы ] [ Загрузки ]**.
- Активная зона занимает весь экран.
- Форма отправки команды на вкладке "Консоль" — закреплена снизу (`position: sticky; bottom: 0`).

#### Поведение JS (`static/app.js`)
- При загрузке: GET `/api/web/devices`, заполнить селектор. Если есть `?device_id=X` в URL — выбрать.
- При выборе устройства: записать в URL (без перезагрузки, через `history.replaceState`), загрузить команды.
- **Polling**: каждые 2 секунды, пока вкладка активна (`document.visibilityState === 'visible'`):
  - GET `/api/web/devices` — обновить online-индикаторы.
  - GET `/api/web/commands?device_id=X&limit=100` — обновить консоль.
- Отправка команды:
  - Заполнить `name`, `payload`, опционально выбрать `upload_id` из dropdown (список грузится из `/api/web/uploads`).
  - POST `/api/web/commands`. Очистить форму при успехе.
- Загрузка файла:
  - На панели Uploads — кнопка "Загрузить", открывает `<input type="file">`.
  - POST `/api/web/uploads` (multipart). Прогресс через `XMLHttpRequest` (или `fetch` — но без прогресса).
- Проводник:
  - GET `/api/web/files?path=...`. Хлебные крошки. Клик на папку — переход. Клик на скачать → window.location = url. Клик на удалить → confirm → DELETE.
- Все ошибки API показываются как toast (простой div сверху на 3 секунды).

#### Подсветка статусов
- `pending` — серый фон.
- `in_progress` — синий фон + вращающийся индикатор.
- `done` — зелёная рамка слева.
- `error` — красная рамка слева, output моноширинно.

Output показывать как `<pre>` с переносом длинных строк.

## 9. Безопасность

1. **Path traversal**: `safe_path(base: Path, user: str) -> Path` — проверка через `realpath` + `is_relative_to`. Применяется в `web_api.files.*`, скачивании uploads, скачивании input/output файлов команд.
2. **Санитизация имён команд**: `re.sub(r'[^A-Za-z0-9_-]', '_', name)`. Если итог пустой — отказ при создании команды (400).
3. **Санитизация имён загружаемых файлов**:
   - убрать `\x00`;
   - заменить разделители путей;
   - срезать ведущие `.`;
   - ограничить длину 200 символов;
   - если итог пустой — `file`.
4. **Лимит загрузки** — стримом, проверяется по ходу записи.
5. **Bearer-токены агентов** — `secrets.token_urlsafe(32)`. Сравнение через `secrets.compare_digest`.
6. **Bcrypt** — для пароля админа.
7. **Сессии** — Starlette `SessionMiddleware`, `httponly`, `samesite=lax`. (HTTPS-флаг — на усмотрение деплоя, в коде не форсить.)
8. **CSRF**: для POST/PUT/DELETE из веб-API проверять заголовок `X-Requested-With: fetch` (фронт его всегда шлёт). Это в сочетании с `samesite=lax` достаточно для одного админа.
9. **Защита от утечки токенов**: токен агента не логировать в полном виде. В логах — только `device_id`.

## 10. Сценарии

**Сценарий 1: первый запуск сервера**
1. Админ редактирует `config.yaml` → запускает `python generate_password.py` → копирует хэш и `session_secret` в конфиг.
2. `python main.py`. Сервер создаёт `data.db`, `cmds/`, `uploads/`. Слушает порт.
3. Открывает в браузере, логинится.

**Сценарий 2: появление устройства**
1. Агент шлёт `POST /api/agent/register`. Получает `device_id` и токен, сохраняет локально.
2. Устройство сразу видно в селекторе админки (после следующего polling-тика).

**Сценарий 3: команда без файлов**
1. Админ выбирает устройство, заполняет name/payload, жмёт "Отправить" → команда `pending` в БД.
2. Агент через ≤2 сек делает `GET /api/agent/command`, получает её, статус → `in_progress`.
3. Агент выполняет, шлёт `POST /api/agent/result` с `status=done`, `output=...`.
4. Через ≤2 сек админ видит результат.

**Сценарий 4: команда с файлом ОТ админа К агенту**
1. Админ заранее загружает файл (раздел Uploads) → `POST /api/web/uploads`.
2. При создании команды выбирает `upload_id` из списка.
3. Агент в ответе `GET /api/agent/command` видит `has_file=true, file_url=...`.
4. Агент шлёт `GET /api/agent/command/{id}/file` со своим токеном — получает файл.
5. Дальше всё как в сценарии 3.

**Сценарий 5: команда с файлом ОТ агента К админу**
1. Команда отправлена обычным способом.
2. Агент в `POST /api/agent/result` прикладывает поле `file`.
3. Сервер сохраняет в `cmds/<name>/<ts>_<filename>`, пишет путь в БД.
4. Админ видит в консоли кнопку скачать output-файл, и/или может найти его в проводнике.

## 11. Ошибки и логирование

- Логирование через стандартный `logging`, формат: `%(asctime)s %(levelname)s %(name)s: %(message)s`. INFO в stdout.
- Каждый запрос агента логируется: `device_id`, метод, путь, статус ответа. Токен — НЕ логировать.
- Веб-логин: успехи и неудачи (с IP) — INFO/WARNING.
- Ошибки FastAPI ловятся стандартными `HTTPException` с понятными `detail`-сообщениями.

## 14. Критерии приёмки

1. `python main.py` запускается без ошибок при правильно заполненном конфиге.
2. С плейсхолдерами в конфиге сервер отказывается стартовать с понятным сообщением.
3. Агент-сценарий: register → get_command → result (с файлом и без) — работает, файлы оказываются в `cmds/<name>/<timestamp>_<filename>`.
4. Сценарий с input-файлом: upload через UI → создание команды с upload_id → агент скачивает файл по `/api/agent/command/{id}/file`.
5. Веб-админка работает на десктопе и нормально выглядит на мобильном (Chrome DevTools, iPhone SE 375px).
6. Polling обновляет статусы команд и online-индикаторы.
7. Path-traversal: попытки `?path=../config.yaml` или `?path=/etc/passwd` отбиваются с 400.
8. Без сессии веб-API возвращает 401, страницы редиректят на `/login`.
9. Без bearer-токена `/api/agent/command` и `/api/agent/result` возвращают 401.
10. Удаление upload, на который ссылается команда, возвращает 409.
11. Файл больше `max_upload_size_mb` отбивается с 413, частично записанный файл удаляется.
12. История команд не теряется (БД не чистится).
